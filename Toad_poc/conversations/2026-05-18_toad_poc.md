## Tool 1 — Sanitizer Design

### Email Mapping Rules
- Domain-aware, consistent, sequential
- Same email always → same mock email across ALL reports
- Domain 1 (abc.co.uk): emailid1@company1.com, emailid2@company1.com...
- Domain 2 (mnk.com):   emailid1001@company2.com, emailid1002@company2.com...
- Domain 3:             emailid2001@company3.com...
- Block size: 1000 IDs per domain

### Replacement Order (to avoid partial matches)
1. Passwords — longest first (prevents `123456` replacing inside `123456789`)
2. UNC paths — longest first (paths share common prefixes)
3. Emails — case-insensitive (XML may have mixed case in UserName= attributes)
4. Oracle schemas
5. Servers
6. Service accounts
7. DSNs (both space-form and URL-encoded form)
8. SMTP servers

### Output per report
- `{report}_sanitized.txt` — sanitized XML (safe to share)
- `{report}_mapping.csv` — per-report subset of global registry
- `global/mapping_registry.csv` — cumulative across all reports

## Tool 1.01 — Mock Data Generator (POC only)

**File:** `tools/tool1_01_mock_data.py`

**Input:** `migration_toolset/input/seed/{report_name}/*.csv`  (user provides 10 actual rows per table)
**Output:** `migration_toolset/reports/{report_name}/mock_data/*.csv`

### Column Type Detection (automatic)
| Detected type | Logic |
|---|---|
| `pk` | Column named exactly `id` |
| `fk_candidate` | Integer column, not PK — FK target resolved by name |
| `datetime` | Matches known datetime formats |
| `date` | Matches known date formats |
| `time` | Matches HH:MM:SS or HH:MM |
| `prefixed_int` | Pattern like WO-00001 — prefix preserved, number increments |
| `decimal` | Float values — preserves decimal places |
| `enum` | 6 or fewer unique values — randomly sampled |
| `string` | High cardinality — randomly sampled from seed |

### FK Detection — Name-based scoring
- Extract prefix before `_id` in column name: `dwor_id_root` -> `dwor`
- Strip leading d/f type indicator: `dwor` -> `wor`
- Match against table name (strip dim_/fct_): `work_orders` starts with `wor` -> match
- All 6 FK columns in fct_gas_escapes_v resolved correctly

## Tool 1.02 — DDL Generator (POC only)

**File:** `tools/tool1_02_ddl_generator.py`

**Input:**

- `reports/{report}/sanitized/{report}_sanitized.txt` — for schema assignment

**Output:** `reports/{report}/ddl/{report}_ddl.sql`

### Type Inference Rules
| SQL Type | Condition |
|---|---|
| `INT NOT NULL` | Column named `id` (PK) or integer values in INT range |
| `BIGINT` | Integer values exceeding INT range |
| `DECIMAL(p,s)` | Float values — precision/scale from data |
| `DATETIME2` | Matches datetime formats |
| `DATE` | Matches date formats |
| `TIME` | Matches HH:MM:SS or HH:MM |
| `CHAR(1)` | Only Y/N values |
| `VARCHAR(n)` | String — sized to standard bucket (10/20/50/100/200/500/1000) |
| `NVARCHAR(MAX)` | String longer than 1000 chars |

### Schema Assignment
- Parses `schema.table` patterns from SQL in sanitized XML
- Correctly assigned: `abcbimart` (6 tables), `MAXRPD` (1 table)
- Falls back to `dbo` if no sanitized XML exists

- 7 tables, 2 schemas (`abcbimart`, `MAXRPD`)
- `fct_gas_escapes_v` detected as view (ends in `_v`) — stored as TABLE with comment
- All PK constraints generated
- Idempotent DDL: wrapped in `IF OBJECT_ID(...) IS NULL` guards

## Tool 2 — ADF ARM Template Generator

**File:** `tools/tool2_adf_generator.py`

**Input:** `reports/{report}/sanitized/{report}_sanitized.txt`
**Output:** `reports/{report}/adf/`
```
linkedServices/   LS_AzureKeyVault.json, LS_AzureSQL_Source.json, LS_AzureBlobStorage.json
datasets/         DS_AzureSQL_{table}.json (one per SQL table), DS_AzureSQL_Config.json,
                  DS_AzureSQL_ODS_Log.json, DS_AzureSQL_ReportSource.json,
                  DS_Blob_Output.json, DS_Blob_Archive.json
pipelines/        PL_{report_name}.json
arm_template.json                         ← deployable ARM template
arm_template_parameters.json              ← parameter template (fill before deploy)
```

### Key design decisions
- Pipeline named from folder name (`PL_BC_BIMIO_267_Daily`), not Toad workflow name (`Workflow1`)
- All secrets via Azure Key Vault — no passwords in templates
- Linked services are **shared** (same 3 LS across all 200+ report pipelines)
- Output directory is wiped clean on each run (no stale files)

### Oracle/Redshift → T-SQL translations
| Pattern | T-SQL |
|---|---|
| `SYSDATE` | `GETDATE()` |
| `trunc(expr)` / `trunc(GETDATE())` | `CAST(expr AS DATE)` (supports nested parens) |
| `date_add('day', n, expr)` | `DATEADD(DAY, n, expr)` |
| `date_trunc('month', expr)` | `DATEFROMPARTS(YEAR(...), MONTH(...), 1)` |
| `DATEDIFF(minutes, ...)` | `DATEDIFF(MINUTE, ...)` |
| `::TIMESTAMP` | `AS DATETIME2` |
| `to_date(col, 'dd/mm/yyyy')` | `CONVERT(DATE, col, 103)` |
| `DECODE(col, 'A', 'B', col)` | `CASE WHEN col='A' THEN 'B' ELSE col END` |

### Pipeline activity chain
```
Lookup_ODS_Refresh_Check (SELECT COUNT(*) → ODS log table, T-SQL translated)
  └── SetVar_ReportDate (yesterday's date, dd.MM.yyyy)
        ├── Lookup_Ops_Email_List   (config.report_email WHERE group='OPERATIONS')
        ├── Lookup_BI_Email_List    (config.report_email WHERE group='BI_TEAM')
        └── Lookup_Alert_Email_List (config.report_email WHERE group='ALERT_ONLY')
              └── If_ODS_Refreshed (@greater(row_count, 0))
                    TRUE:  Copy_ReportData_To_Blob → Copy_Archive_File
                               → Email_Report_To_Operations → Email_Confirmation_To_BI_Team
                    FALSE: Email_ODS_Not_Refreshed
```

### Test Run (BC_BIMIO_267_Daily)
```
3 linked services, 11 datasets, 1 pipeline (6 top-level activities), 16 ARM resources
ODS SQL: SELECT COUNT(*) AS row_count FROM MAXRPD.T_ODS_LOG WHERE CAST(ems AS DATE) = CAST(GETDATE() AS DATE)
Email subjects extracted from Toad XML, #date# substituted with variables('report_date')
```

### Bugs fixed during testing
- f-string backslash in expression (SyntaxError) → fixed string concatenation
- `trunc(GETDATE())` not translated — regex `[^()]+` rejects nested parens → `(?:[^()]+|\([^()]*\))+`
- Duplicate `DS_AzureSQL_ODS_Log` + `DS_AzureSQL_t_ods_log` → skip ODS table from per-table loop
- Pipeline name mismatch (ARM used folder name, JSON used Toad workflow name) → aligned both to folder name

### Usage
```bash
python tool2_adf_generator.py BC_BIMIO_267_Daily
python tool2_adf_generator.py BC_BIMIO_267_Daily -v   # show extraction details
```

## Tool 3 — Config Schema + Data Setup

**File:** `tools/tool3_config_setup.py`

**Input:** `reports/{report}/sanitized/{report}_sanitized.txt`
**Output:**
- `global/config/config_schema_ddl.sql` — CREATE SCHEMA + CREATE TABLE DDL (created once, skipped if exists)
- `reports/{report}/config/{report}_config_data.sql` — per-report INSERT statements

### Tables created
| Table | Purpose |
|---|---|
| `config.report` | One row per report: name, pipeline_name, description, schedule_time, output_container, is_active |
| `config.report_email` | Email distribution: report_id FK, email_address, recipient_group (OPERATIONS/BI_TEAM/ALERT_ONLY), email_type (TO/CC/BCC), is_active |

### Email grouping heuristic
- Finds all `SendEmailActivity` elements in sanitised XML
- Main report email = activity with most `To` recipients
- Its `To` → OPERATIONS / TO
- Its `Cc` → ALERT_ONLY / CC
- Its `Bcc` → BI_TEAM / BCC
- Remaining activities: error/exception emails → ALERT_ONLY; others → OPERATIONS

### Test Run (BC_BIMIO_267_Daily)
```
15 email addresses across 3 groups:
  OPERATIONS  TO   : emailid2-10  (9 people — main report recipients)
  ALERT_ONLY  CC   : emailid11, emailid12, emailid15  (CC on main email)
  BI_TEAM     BCC  : emailid1, emailid13, emailid14   (BCC + confirmation)
```

### Both scripts are idempotent (safe to re-run)
- `config.report`: IF NOT EXISTS guard on report_name
- `config.report_email`: IF NOT EXISTS guard on (report_id, email_address, recipient_group)
- Ends with a SELECT to verify inserted data

### Run order
```bash

sqlcmd -S <server> -d <db> -i global/config/config_schema_ddl.sql

# Step 2 — once per report
sqlcmd -S <server> -d <db> -i reports/BC_BIMIO_267_Daily/config/BC_BIMIO_267_Daily_config_data.sql
```

## Tool 4 -- ADF Deployment Scripts

**File:** `tools/tool4_adf_deploy.py`

**Input:** `reports/{report}/adf/arm_template.json` + `arm_template_parameters.json`
**Output:** `reports/{report}/adf/deploy/`
```
deploy_bootstrap.ps1 / .sh          -- factory + linked services (run once per environment)
deploy_{report}.ps1  / .sh          -- datasets + pipeline (run per report)
arm_template_bootstrap.json         -- split ARM: factory + LS only
arm_template_report.json            -- split ARM: datasets + pipeline only
deployment_checklist.txt            -- parameter status + run order
```

### Key design decisions
- Does NOT execute any az CLI commands -- generates scripts only (no real Azure access)
- Splits the combined ARM template into two: bootstrap (shared, once) + report (per-report)
- This avoids redeploying shared Linked Services on every pipeline update for 200+ reports
- Validates JSON structure locally; checks for unfilled `<your-...>` placeholders
- Checklist shows [OK] / [!!] per parameter, plus full resource list and run order

### Split ARM template resources
| Script | Resources |
|---|---|
| `deploy_bootstrap` | factories (1), linkedservices (3) |
| `deploy_{report}` | datasets (11), pipelines (1) |

### Deployment flow (user-run, after filling parameters)
```
Step 1  az login
Step 2  deploy_bootstrap.ps1   (once: creates ADF factory + 3 linked services)
Step 3  deploy_{report}.ps1    (per report: 11 datasets + 1 pipeline, Incremental mode)
```

## Tool 5 -- Blob Upload Scripts

**File:** `tools/tool5_blob_upload.py`

**Input:** `reports/{report}/sanitized/{report}_sanitized.txt`
**Input (user-supplied):** `global/xlsm_templates/{report_name}/*.xlsm`
**Output:** `reports/{report}/blob/`
```
upload_{report}.ps1       -- az storage blob upload script (PowerShell)
upload_{report}.sh        -- az storage blob upload script (bash)
blob_checklist.txt        -- file presence status + action list
```

### What it does
- Extracts expected xlsm filename from sanitised XML (CopyFileActivity DestinationFileName)
- Checks if the file has been placed in `global/xlsm_templates/{report_name}/`
- Reads storage account name from Tool 2's parameters file
- Generates upload script targeting `templates/{report_name}/{filename}.xlsm` in Blob Storage
- Does NOT connect to Azure or run any az CLI commands

### Template detection priority
1. `CopyFileActivity DestinationFileName` -- most reliable (explicit xlsm name)
2. `FileDescription Description="Copy_N: filename.xlsm"` -- email attachment label
3. `BodyFileName` UNC path -- fallback

## Tool 3 Update — SQL + Template Support

**Changes made in this session continuation:**

### New tables in config schema DDL
| Table | New columns |
|---|---|
| `config.report` | `template_name VARCHAR(500) NULL`, `template_blob_path VARCHAR(500) NULL` |
