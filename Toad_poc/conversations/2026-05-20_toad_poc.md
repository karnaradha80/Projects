## Session 2 — Generic ADF Pipeline Architecture (Option A)

### What Changed

Refactored the ADF pipeline generation from per-report pipelines to a single **generic pipeline per category** (`PL_Generic_Daily`, `PL_Generic_Weekly`, etc.) that reads all SQL queries and email addresses from the config database at runtime.

**Decision:** User confirmed Option A — implement the generic pipeline now, not defer to production.

---

### Tool 2 — `tool2_adf_generator.py` (full rewrite of pipeline section)

**Before:** Generated `PL_BC_BIMIO_267_Daily` per report with hardcoded SQL and hardcoded email addresses.

**After:** Generates `PL_Generic_Daily` (one pipeline per category) with:
- `report_name` pipeline parameter — passed at runtime by the trigger
- 9 activities using ADF `@concat` expressions to read SQL/emails from config at runtime:

| Activity | Type | Purpose |
|---|---|---|
| `Lookup_Report_Config` | Lookup | Reads `output_container` from `config.report` using `@pipeline().parameters.report_name` |
| `Lookup_ODS_SQL` | Lookup | Reads ODS check query text from `config.report_sql` WHERE `query_type = 'ODS_CHECK'` |
| `Lookup_ODS_Refresh_Check` | Lookup | Executes `@activity('Lookup_ODS_SQL').output.firstRow.query_text` — dynamic SQL |
| `SetVar_ReportDate` | SetVariable | Sets yesterday's date |
| `Lookup_Main_SQL` | Lookup | Reads main report query from `config.report_sql` WHERE `query_type = 'REPORT_MAIN'` |
| `Lookup_Ops_Email` | Lookup | Reads OPERATIONS/TO email list |
| `Lookup_BI_Email` | Lookup | Reads BI_TEAM/BCC email list |
| `Lookup_Alert_Email` | Lookup | Reads ALERT_ONLY/CC email list |
| `If_ODS_Refreshed` | IfCondition | TRUE: Copy → Archive → Email ops/BI; FALSE: ODS alert email |

**Copy activity uses:** `sqlReaderQuery: "@activity('Lookup_Main_SQL').output.firstRow.query_text"` — this is the key dynamic SQL pattern.

**Datasets (3 total, generic):**
- `DS_AzureSQL_Config` — all SQL lookups use `sqlReaderQuery` override; no per-report table binding
- `DS_Blob_Generic_Output` — parameterized by `container` + `file_name`
- `DS_Blob_Generic_Archive` — parameterized by `container` + `archive_file_name`

**ARM template split (updated):**
- `arm_template_bootstrap.json` — factory + LS + datasets + `PL_Generic_Daily` (deploy ONCE per category)
- `arm_template_report.json` — `TR_BC_BIMIO_267_Daily_0600` trigger ONLY (deploy per report)

**Trigger passes `report_name` as parameter:**
```json
"pipelines": [{"pipelineReference": {"referenceName": "PL_Generic_Daily"}, "parameters": {"report_name": "BC_BIMIO_267_Daily"}}]
```

## Bug Fix — Single Report sidebar not showing new files

**Root cause:** The sidebar "Single Report" selectbox called `_existing_reports()` which only lists folders already present in `reports/`. New input files (268–272) have no report folder yet, so they were invisible in the dropdown.

**Fix (`migration_toolset/UI/app.py`, commit `fc57b2a4`):**
- Removed the inner "Choose existing / Enter name" radio
- Replaced with a single unified selectbox that merges:
  - `reports/` folders → shown as `name  ✅`
  - `input/` files (not yet processed) → shown as `name  (new)`
- Kept a "Or type name manually" text input as fallback
- Selecting a `(new)` report sets `report_name` so Tab 1 can sanitize it immediately
