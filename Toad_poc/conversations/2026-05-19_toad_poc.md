## Session 3 — Database Execution + Branding (2026-05-19 continued)

### Bug Fix
- `registry.save()` → `registry._save()` in `app.py` (both single and batch mode) — `MappingRegistry` only exposes `_save()` not `save()`

### Database Script Execution Integrated into Tab 4 Auto-Deploy

`_run_az_deploy()` now runs in two phases:

**Phase 1 — ADF ARM Template Deployment** (unchanged)
1. Set subscription
2. Ensure resource group exists
3. Deploy ARM template

**Phase 2 — Database Script Execution** (new)
4. Retrieve SQL password from Key Vault (`kv-toad-poc` → secret `azuresql-db-password`)
5. Execute `global/config/config_schema_ddl.sql` (config schema — once per environment)
6. Execute `reports/{name}/config/{name}_config_data.sql` (per-report config INSERTs)
7. Execute `reports/{name}/ddl/{name}_ddl.sql` (mock table DDL — skipped if not generated yet)

**SQL execution method:** `pyodbc` with ODBC Driver 18 for SQL Server (already installed). `sqlcmd` used if found on PATH; pyodbc is the fallback.

**Notes:**
- All SQL scripts are idempotent — safe to re-run
- If Key Vault password retrieval fails → ADF deploy still succeeds, DB steps skipped with warning
- Table DDL only exists after running Tab 6 POC Tools (Tool 1.01 + 1.02)
